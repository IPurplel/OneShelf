## Official Source Registry — 2026-09-21

A further explicit requirement: discover, review, install, update and reinstall the official adapters from
Sources, through the existing Registry architecture, beside the bundled path. Done without a second plugin
system: `registry/` is generated by `plugins.registry_tool` with the same builder as the bundled bootstrap,
so a fresh library reads all eight as Installed; the API sets the Registry against the library, reviews a
package without installing it, and binds the install to the reviewed sha256; an explicit Registry action
makes a plugin `channel = registry`, which the bundled bootstrap never touches. Compose defaults
`ONESHELF_REGISTRY_URL` to this repository's index over HTTPS.

Found and fixed on the way (ISSUES I-35…I-40): `_record` re-enabled a disabled plugin on any activation; a
package location could escape to another repository on the same host; a refused registry URL stopped the
application from starting; the `/review` route tripped the §49 social-surface guard; an update waiting for
review could not be approved from the Registry; a removed source was still listed as installed.

REL-12, REL-13 and REL-15 are `VERIFIED`, live against the real application and the GitHub-hosted Registry.
REL-14 is **IMPLEMENTED — BLOCKED ON OWNER SIGNING KEY**: the signing and verification chain is complete and
tested with test-only keys, but no production key exists and none was generated for the owner, so the
published Registry is unsigned and its entries install as Community. The one-time owner process is in
`docs/plugins.md` §7.

## Official sources install themselves — 2026-09-21

A further explicit requirement: a fresh install must open with its eight official sources, with nothing to
build, upload or approve. Done through the existing plugin architecture and nothing else — each adapter is
built with the one deterministic builder and installed with `PluginManager.install_file`, packaged tests
included, as `official`/`bundled`.

It runs once. A marker in `app_meta` and a per-source record in `bundled_plugins` (migration 0014) mean a
restart, rebuild, recreation or update never runs it again, so a disabled source stays disabled and a
removed one stays removed. Updates keep rollback and approve nothing new; a version asking for more waits for
review. A disabled adapter is not updated, because installing a version would re-enable it. A broken one is
never active, is raised in Needs Attention, and does not block readiness — §3.3 says local content must not
depend on any source. An interrupted bootstrap resumes rather than mistaking its own work for the person's.

Verified in-process and live against the real application: REL-10 is `VERIFIED`. The production image is
checked statically and in the host gate, which now asserts the eight sources and that the person's choices
survive restart, recreation and update — REL-11 stays `BLOCKED` until that runs.
