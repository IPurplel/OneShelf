## 1. ما هو OneShelf

OneShelf مكتبة قراءة شخصية تعمل على جهازك أنت (self-hosted)، لمستخدم واحد، بلا حساب سحابي وبلا أي
اتصال خارجي غير المصادر التي تختارها. تجمع المانغا والمانهوا والمانهوا الصينية والقصص المصوّرة والكتب
والروايات والأبحاث في مكتبة واحدة:

- **تبحث** في المصادر التي ثبّتها (مثل MangaDex وWEBTOON وGutenberg) وفي مكتبتك المحلية معًا.
- **تقرأ** أونلاين أو من الملفات المحمّلة (صور صفحات، EPUB، PDF، نصوص).
- **تنزّل** ما تطلبه أنت فقط، وتحفظه في مجلد بشري مقروء على قرصك.
- **تتابع** الأعمال وتخبرك بالفصول الجديدة، بدون تنزيل تلقائي.
- **تحفظ** تقدّم القراءة والمفضلة والوسوم والملاحظات.
- **تنسخ احتياطيًا وتستعيد وتصدّر** المكتبة.

الإحساس المطلوب: «مكتبتي الشخصية ومكان قراءتي»، وليس «لوحة تحكم لسحب البيانات». لذلك التفاصيل التقنية
مخفية وتظهر تدريجيًا عند الحاجة فقط.

### المبادئ المؤسسة (تنطبق على كل جزء)

| المبدأ | المعنى العملي |
|---|---|
| سلامة المصدر واللغة | لا تبديل صامت للمصدر أو اللغة أبدًا. يمكن تغيير **طريقة** الاستخراج فقط، وليس المصدر ولا اللغة. |
| «غير معروف» حالة صحيحة | البيانات الناقصة ليست فشلًا. `unknown` لا تتحوّل أبدًا إلى «لا» أو «غير متاح». |
| استقلال المحتوى المحلي | الملف المحمّل يبقى قابلًا للقراءة حتى لو اختفى المصدر أو عُطّلت الإضافة أو انقطع الإنترنت. |
| لا حذف خفي | لا يُحذف شيء لأن المصدر توقف عن عرضه، ولا يُعتبر قرص غير موصول «محذوفًا». |
| الأفعال مستقلة | الإزالة من الرف، وإلغاء المتابعة، وحذف الملفات ثلاثة أفعال منفصلة تمامًا. |
| الإضافات بيانات لا كود | المصدر الخارجي ملف وصفي (YAML) لا يُنفَّذ منه أي كود. |

## 2. الصورة الكبيرة

```
 المتصفح (React SPA)  ──HTTP/JSON + SSE──►  FastAPI (عملية واحدة، منفذ 8420)
                                              │
        ┌─────────────────────────────────────┼──────────────────────────────────────┐
        │ RequestGuard (Host + Origin)  →  AccessBoundary (loopback / LAN / remote)   │
        └─────────────────────────────────────┼──────────────────────────────────────┘
                                              ▼
                                   Routers في oneshelf/api/
                                              │
                                              ▼
                     الخدمات (Services) — منطق المجال كله هنا
   search · catalog · downloads · reader · shelf · follow · notifications · storage ·
   backup · restore · export · auth · generator · health
                │                         │                              │
                ▼                         ▼                              ▼
       SQLite (oneshelf.db)      نظام الملفات (storage roots)    SourceService
       + cache.db + secrets.db   staging → commit journal         │
                                                                   ▼
                                              PluginRuntime (recipes) ← PluginManager (.osp)
                                                                   │
                                                                   ▼
                                       TrafficGovernor (أولويات/حدود) + EgressPolicy (SSRF)
                                                                   │
                                                                   ▼
                                              HTTP client / Chromium عبر egress proxy
                                                                   │
                                                                   ▼
                                                        مواقع المصادر على الإنترنت
```

- **عملية واحدة**: الواجهة تُبنى أثناء بناء الصورة، ويقدّمها نفس خادم الـ API من نفس الأصل (ADR 0001).
- **SQLite** هي مصدر الحقيقة الوحيد للحالة. الملفات في مجلدات التخزين، وقاعدة البيانات تشير إليها.
- **كل اتصال بالمصادر** يمر عبر المنظّم المروري وسياسة الخروج، ولا تملك أي إضافة عميل HTTP خاص بها.
- **الأحداث الحية** تصل للواجهة عبر بث SSE واحد (`/api/events`)، فتحدّث الشاشات نفسها بدون polling.

## 3. خريطة المستودع

```
OneShelf/
├── backend/                 الخادم (Python 3.13, FastAPI, SQLite)
│   ├── oneshelf/            كود التطبيق — انظر الجدول التالي
│   ├── plugins/official/    لقطة المصادر الرسمية المدمجة (لا تُعدّل يدويًا)
│   ├── plugins/*.py         أدوات بناء الحزم ومزامنة اللقطة (build, sync_snapshot, registry_tool)
│   ├── testsource/          «مصدر الاختبار»: موقع وهمي محلي (aiohttp) لكل سيناريوهات الاختبار
│   ├── tests/               unit / integration / deploy (≈1600 اختبار)
│   ├── pyproject.toml       الاعتماديات والإعدادات
│   └── requirements.lock    الاعتماديات المثبتة بإصدارات محددة
├── frontend/                الواجهة (React 19 + TypeScript + Vite 7)
│   └── src/                 انظر القسم 18
├── deploy/                  Dockerfile, compose.yaml, container_start.py, healthcheck.py, nginx/
├── docs/                    هذا المرجع + operations / api / plugins / development / adr / ledger
├── install.sh / update.sh / uninstall.sh   سكربتات التثبيت والتحديث والإزالة (Linux)
├── .env.example             كل إعدادات النشر موثّقة
└── README.md                دليل المستخدم
```

### وحدات الخادم (`backend/oneshelf/`)

| المجلد | المسؤولية |
|---|---|
| `api/` | الـ routers (HTTP)، وحارس الطلبات، وحد الوصول، و`app.py` الذي يربط كل شيء |
| `auth/` | الوصول عن بعد: passkeys (WebAuthn)، الجلسات، رمز الاسترداد، سياسة الشبكات الموثوقة |
| `backup/`, `restore/`, `export/` | النسخ الاحتياطي (مكتبة/كامل)، الاستعادة (دمج/استبدال)، التصدير |
| `catalog/` | نموذج ثقة الفهرس (Trusted/Suspicious) |
| `db/` | الاتصال (WAL, FULL sync) والترحيلات `schema/NNNN_*.sql` |
| `diagnostics/` | سجل تشخيص محلي محجوب البيانات الحساسة، 7 أيام أو 100MB |
| `discovery/` | منطق الصفحة الرئيسية (Hero, Trending, Latest, Recently Added) و«استكشف» (`discover.py`) |
| `downloads/` | محرك التنزيل، عقد الاستخراج، المشغّل الخلفي |
| `events/` | ناقل الأحداث الداخلي وبث SSE |
| `follow/` | المتابعة واكتشاف الإصدارات الجديدة والمجدول |
| `generator/` | مولّد الإضافات من رابط موقع، وإصلاح الإضافات |
| `health/`, `sources/health.py` | صحة المصادر على مستوى كل قدرة |
| `importer/` | استيراد CBZ/PDF/EPUB إلى «مسار محلي» |
| `integrity/` | فحص الملفات (الصيغة من المحتوى، حماية zip-bomb وzip-slip) |
| `library/` | الرف، تصحيحات المستخدم، النسخ المحلية، إعادة التصنيف |
| `net/` | عميل HTTP، سياسة الخروج، المنظّم، المتصفح والوكيل، نقل ECH الخاص بـ Noor |
| `notifications/` | الإشعارات و«يحتاج انتباهك» |
| `plugins/` | تحميل الحزم والتحقق منها، والتشغيل، والإدارة، والسجل (Registry)، والإضافات المدمجة |
| `reader/` | صفحات القارئ (محلي/كاش/أونلاين)، كاش القارئ، التقدّم، العلامات |
| `search/` | البحث المحلي أولًا، التجميع، الترتيب، كاش الاكتشاف، فتح رابط مباشر |
| `services/` | استرداد الإقلاع، المهام الخلفية، تشغيل الأعمال الثقيلة خارج حلقة الأحداث |
| `sessions/` | «استخدم جلستي»: تسجيل الدخول للمصادر وتخزين الجلسة مشفرة |
| `settings/defaults.py` | **المكان الوحيد** للقيم الافتراضية |
| `storage/` | مواقع التخزين، التخطيط، الـ staging، سجل الالتزام (commit journal)، الماسح، الترحيل |
| `text/` | تطبيع العربية للبحث، وحدات النص (`.ostext`)، تنقية HTML |

## 4. التشغيل: الإنتاج والتطوير

### 4.1 الإنتاج (Docker/Podman)

```sh
./install.sh      # أول مرة: يبني الصورة ويجهز المجلدات ويشغّل
./update.sh       # يسحب آخر نسخة من origin/main ويعيد البناء ويشغّل
./uninstall.sh    # يوقف ويحتفظ بكل البيانات
```

- الصورة مبنية على مرحلتين (`deploy/Dockerfile`): مرحلة Node تبني الواجهة، ثم Python 3.13 slim مع
  Chromium (Playwright) وتنسخ الواجهة المبنية إلى `/app/web`.
- تعمل الحاوية بمستخدم غير مميّز (uid 10001)، وبشبكة المضيف (`network_mode: host`) حتى يرى التطبيق
  عنوان الزائر الحقيقي (ADR 0003).
- **خمسة مجلدات دائمة** (bind mounts، ADR 0002):

| على المضيف (افتراضيًا) | داخل الحاوية | المحتوى |
|---|---|---|
| `deploy/volumes/data` | `/data` | `oneshelf.db`، `cache.db`، `secrets.db`، staging، diagnostics، snapshots |
| `deploy/volumes/content` | `/content` | الملفات المحمّلة والمستوردة (موقع تخزين) |
| `deploy/volumes/plugins` | `/data/plugins` | حزم المصادر المثبتة |
| `deploy/volumes/keys` | `/keys` | مفتاح تشفير جلسات المصادر — **انسخه احتياطيًا بنفسك** |
| `deploy/volumes/backups` | `/data/backups` | ملفات `.osbackup` |

- **lan-proxy**: حاوية Nginx اختيارية (مفعّلة افتراضيًا) تقدّم OneShelf للشبكة المحلية على المنفذ 80، بينما
  يبقى التطبيق نفسه على `127.0.0.1:8420`. هي المصدر الوحيد الموثوق لعنوان الزائر عبر `X-Forwarded-For`.
- `deploy/container_start.py` يتحقق من المجلدات القديمة، ويضيف عنوان الـ proxy للموثوقين، ويحوّل رابط
  الـ Registry القديم للجديد، ثم يشغّل التطبيق.
- `update.sh` يرفض التحديث إذا كانت في المستودع تعديلات غير محفوظة على ملفات متتبَّعة، أو إذا كان الفرع
  غير `main`. يتحقق كذلك من الصحة عبر `/api/ready` بعد التشغيل.
- كل الإعدادات في `.env` في جذر المستودع (انظر `.env.example`): `ONESHELF_BIND`، `ONESHELF_PORT`،
  `ONESHELF_TRUSTED_NETWORKS`، `ONESHELF_ALLOWED_HOSTS`، `ONESHELF_*_PATH`، `ONESHELF_REGISTRY_URL`...

### 4.2 التطوير المحلي

**الخادم:**

```sh
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements.lock && .venv/bin/pip install -e .
ONESHELF_DATA_DIR=.oneshelf-dev .venv/bin/python -m oneshelf          # http://127.0.0.1:8420
```

**مصدر الاختبار** (موقع وهمي محلي فيه كل الحالات: مانغا، كتب، عربي، صفحات مكسورة، حد طلبات...):

```sh
.venv/bin/python -m testsource 8421
ONESHELF_DEV_TEST_SOURCE=1 ONESHELF_DEV_TEST_SOURCE_ADDRESS=127.0.0.1:8421 \
  ONESHELF_DATA_DIR=.oneshelf-dev .venv/bin/python -m oneshelf
```

ثم ابنِ حزمته وثبّتها: `testsource.build.build_package(...)` ثم `POST /api/sources/uploads` و
`POST /api/sources/install`. يُتحكّم بسيناريوهاته عبر `POST /__control` على منفذه.

**الواجهة:**

```sh
cd frontend && npm install && npm run dev      # http://localhost:5173 ، يمرّر /api إلى 8420
npm run typecheck    # tsc --noEmit
npm test             # vitest
npm run build        # بناء الإنتاج
```

> **مهم:** لا توجّه `ONESHELF_DATA_DIR` ولا مواقع التخزين إلى مكتبتك الحقيقية أثناء التجارب.

## 5. مسار الطلب والأمان

كل طلب HTTP يمر بطبقتين قبل الـ router، بهذا الترتيب:

1. **`RequestGuardMiddleware`** (`api/guard.py`):
   - رأس `Host` يجب أن يكون IP أو `localhost` أو اسمًا في `ONESHELF_ALLOWED_HOSTS` أو اسم النطاق المعتمد
     للوصول البعيد. هذا يحمي من هجمات DNS rebinding. الرفض: `421 HOST_NOT_ALLOWED`.
   - أي طلب يغيّر الحالة (`POST/PUT/PATCH/DELETE`) يجب أن يكون من نفس الأصل (`Origin` و`Sec-Fetch-Site`)،
     وهذا يمنع CSRF من مواقع خبيثة مفتوحة في متصفح على نفس الشبكة.
2. **`AccessBoundaryMiddleware`** (`api/middleware.py` + `api/access.py`) يصنّف العميل حسب **عنوانه الحقيقي**
   وليس حسب أي رأس يرسله:
   - `loopback` (نفس الجهاز): موثوق.
   - `lan` (ضمن `ONESHELF_TRUSTED_NETWORKS` أو ما أُضيف من الإعدادات): موثوق بالكامل.
   - `remote`: يجب أن يحمل كوكي جلسة `oneshelf_remote` صالحًا، تُنشأ بعد تسجيل الدخول بـ **passkey**.
     الاستثناء الوحيد هو مسارا تسجيل الدخول نفسيهما.
   - `X-Forwarded-For` لا يُقرأ إلا من عناوين `ONESHELF_TRUSTED_PROXIES`.

**الوصول عن بعد (`auth/`):**

- Passkeys مربوطة باسم نطاق HTTPS معتمد. لا يوجد اسم مستخدم ولا كلمة مرور.
- تسجيل passkey جديد يحتاج تفويضًا: اتصالًا من الشبكة المحلية، أو رمز استرداد، أو جلسة بعيدة قائمة.
- رمز الاسترداد يُعرض مرة واحدة ويُخزّن كـ scrypt verifier.
- «استرداد LAN» يمسح الـ passkeys والجلسات البعيدة فقط، ولا يلمس المكتبة.
- رمز الجلسة لا يوجد إلا في كوكي HttpOnly، ولا يُخزّن في localStorage إطلاقًا (فيه اختبار يفرض ذلك).

**أمان المحتوى:** صفحات القارئ والأغلفة تُقدَّم بـ `Content-Security-Policy: sandbox` و`nosniff`، وHTML الكتب
والنصوص يُنقّى بقائمة سماح على الخادم (`text/sanitise.py`) ومرة ثانية في الواجهة (`reader/epub.ts`).

## 6. الإقلاع وربط الخدمات

`api/app.py` → `create_app(config)`، وتعمل دالة `lifespan` عند التشغيل بهذا الترتيب:

1. `migrate()`: ترحيلات أمامية فقط، كل ترحيل في معاملة، مع لقطة متسقة لقاعدة البيانات قبل التغيير
   (`data/snapshots/`). قاعدة بيانات أحدث من الكود تُرفض بدون تعديل.
2. `run_startup_recovery()` (`services/startup.py`) بترتيب إلزامي:
   1. `recover_jobs`: مهام التنزيل التي كانت شغالة ترجع `RECOVERING`، والاستيرادات المعلّقة تفشل.
   2. `recover_commits`: إعادة تشغيل كل التزام مفتوح في `commit_journal` حتى يكتمل أو يُلغى.
   3. `reconcile`: الماسح يطابق السجلات مع الملفات الفعلية (§13).
   4. `clean_staging`: حذف مناطق staging اليتيمة المثبت يُتمها فقط.
3. بناء الخدمات: `PluginManager` و`SessionManager` و`TrafficGovernor` و`SourceService` و`DownloadEngine`
   و`ReaderService` و`ShelfService` و`FollowService` و`NotificationService`... داخل كائن `Services` واحد
   يصل إليه كل router عبر `request.app.state.services`.
4. `sync_bundled()`: تثبيت المصادر الرسمية المدمجة **مرة واحدة** لمكتبة جديدة (انظر §8.6).
5. تشغيل المشغّلات الخلفية: `DownloadRunner` (يحرّك طابور التنزيل)، و`FollowRunner` (فحص المتابعات كل
   12 ساعة تقريبًا)، و`BackupRunner` (نسخة مكتبة كل 7 أيام).

نقاط الحالة:
- `GET /api/health`: هل الخدمة حية، ونسخة المخطط، وتصنيف العميل.
- `GET /api/ready`: هل الترحيلات طُبّقت والاسترداد انتهى، ومواقع التخزين متاحة. يستخدمه healthcheck.

الأعمال الثقيلة (النسخ الاحتياطي، الاستعادة، التصدير، الترحيل، الفحص، حساب SHA للملفات الكبيرة) تعمل في
**worker thread باتصال SQLite خاص** (`services/worker.py`) حتى لا تتجمد الواجهة والقارئ. ويمكن طلبها
بـ `?background=true` فترجع رقم مهمة فورًا (`services/tasks.py`).

## 7. نموذج البيانات

### 7.1 المفاهيم

```
Work (عمل منطقي: "Solo Leveling")
 ├── work_aliases           أسماء بديلة
 ├── source_listings        ما أرجعه كل مصدر (هوية خاصة بالمصدر + رابط + غلاف)
 └── source_tracks          العمل كما يقدّمه مصدر واحد بلغة واحدة  (لا تُخلط أبدًا)
      ├── catalog_snapshots / snapshot_units     لقطات الفهرس (Trusted / Suspicious)
      └── reading_units      وحدة قراءة: فصل، خاص، مقدمة، ون-شوت...  (ليست بالضرورة رقمًا)
           ├── assets          ملف محمّل/مستورد (cbz/pdf/epub/text) في موقع تخزين
           ├── reading_state   حالة القراءة + الموضع + revision
           ├── reading_bookmarks / reading_highlights
           └── download_jobs   مهام التنزيل
```

- **`kind` للمسار:** `source` (من مصدر) أو `local` (مستورد). المسار المحلي عضو كامل الحقوق، ويُقرأ ويُصدَّر
  بدون أي إضافة.
- **ترتيب الوحدات** هو ترتيب المصدر (`source_order`). الترقيم المعروض: رقم المصدر، ثم رقم مشتق، ثم «غير
  معروف». الرقم المشتق للعرض فقط، وليس هوية.
- **`content_type`** للعمل: `manga, manhwa, manhua, comic, book, novel, paper, other, unknown`.
  أولوية التصنيف: تصحيح المستخدم، ثم تصنيف المصدر الصريح، ثم الافتراضي في الإضافة، ثم unknown
  (`plugins/classification.py`).
- **تصحيحات المستخدم** (`library/overrides.py`، جدول `user_overrides`) تُعاد تطبيقها بعد كل تحديث من
  المصدر، فلا يمسحها التحديث أبدًا.
- **قرارات الربط** (`search/mapping.py`، جدول `work_mappings`): Merge / Split / Unlink / Never Match. قرار
  المستخدم يغلب دائمًا.

## 8. المصادر والإضافات (.osp)

### 8.1 الحزمة بيانات وليست كودًا

ملف `.osp` هو ZIP بهذا الشكل:

```
manifest.yaml            الهوية، القدرات، النطاقات المسموحة، المصادقة الاختيارية، اللغة الافتراضية
source.yaml              base URL، أنماط الروابط، حدود الطلبات، المهل
recipes/<capability>.yaml
tests/tests.yaml         حالات اختبار إلزامية
tests/fixtures/…         صفحات ملتقطة تُختبر عليها الوصفات بدون إنترنت
```

**القدرات القياسية:** `search, work, catalog, reader, downloads, latest, health` (+ `check_session`).

**الوصفة (recipe)** = طلب + استخراج: قالب URL، و`fetch: http|browser`، و`response.format: json|html`،
وحقول تُستخرج بـ `css` أو `xpath` أو `json` أو `template`، مع سلسلة تحويلات آمنة محددة
(`trim, extract_number, normalize_arabic, parse_date, regex_extract`...، والتعابير النمطية RE2 خطية الزمن)،
وترقيم صفحات `offset | page_number | next_link`. التفاصيل الكاملة في `docs/plugins.md`.

**وصفة `reader` ترجع واحدًا من اثنين:**
- `url` لكل صفحة: صور، تُقرأ في قارئ الصفحات وتُحمَّل كـ **CBZ**.
- `html` لكل وحدة (API 1.2): نص، يُقرأ في Book Reader ويُحمَّل كـ **`.ostext`**.

### 8.2 مسار التثبيت (`plugins/manager.py` → `install_file`)

نسخ → hash/توقيع → manifest → توافق API → فحص الوصفات والنطاقات والقدرات → فحوص ساكنة
(`plugins/package.py`) → **تشغيل الاختبارات المرفقة** → تفعيل ذري.

- **الصلاحيات تُشتق من الـ manifest** ولا تُعلن يدويًا: `network:domain:…`، `network:cdn:…`،
  `browser:<capability>`، `session:required|optional:<capability>`. يوافق المستخدم على القائمة بالضبط، وأي
  تحديث يطلب أكثر **ينتظر مراجعة جديدة** بينما تبقى النسخة الحالية شغالة.
- تعطيل وتفعيل، والرجوع لنسخة سابقة (`rollback`)، وإزالة الملفات فقط مع إبقاء سجلات المكتبة.

### 8.3 التشغيل (`plugins/runtime.py`)

يأخذ الوصفة ويبني الطلب، ثم يطلب من **جالب Core** (`sources/fetcher.py`) تنفيذه، ثم يستخرج نتائج typed
(`plugins/results.py`) ويسجّل **دليل اكتمال** (هل انتهى الترقيم؟). لا يلمس قاعدة البيانات ولا الملفات ولا مواد
الجلسة الخام. `SourceService.run(plugin_id, capability, inputs, priority=...)` هو الباب الوحيد لتشغيل قدرة.

قدرات القوائم (`search`، `latest`، `trending`) تقبل **نافذة صفحات** `pages=(first, count)`: تقرأ صفحات محددة بدل
كل `max_pages` في الوصفة. لا تبدأ النافذة أعمق من الصفحة 200 ولا تتجاوز حد الوصفة، والقائمة التي تُرقَّم بـ
`next_link` أو بلا ترقيم لا تُقرأ إلا من صفحتها الأولى. «استكشف» يطلب صفحة واحدة في كل مرة.

### 8.4 «استخدم جلستي» (`sessions/`)

للمصادر التي تحتاج تسجيل دخول: يفتح Core متصفحًا معزولًا ويبث شاشته للمستخدم، والمستخدم يسجل الدخول
بنفسه. لا يقرأ OneShelf كلمات المرور ولا يخزّنها. تُلتقط الكوكيز والتخزين المحدودة بنطاقات الجلسة المعلنة،
وتُتحقق بـ `check_session`، وتُخزّن مشفرة في `secrets.db`. الإضافة لا ترى الجلسة أبدًا، وCore يضيف رأس
الكوكي لكل طلب مسموح فقط. حالاتها: `not_connected ↔ checking ↔ connected ↔ needs_reconnect`.

### 8.5 مصادر خاصة

- **Noor Book** (`plugins/native/noorbook.py` + `net/ech.py`): استثناء «أصلي» مراجَع (API 1.3) لأن الموقع
  يحتاج Encrypted Client Hello. كل حركة TLS تبقى داخل سياسة Core.
- المصادر التي **تعرض فقط** بدون قراءة ولا تنزيل: القارئ يعرض «افتحه على موقع المصدر» (`kind: external`).

### 8.6 المصادر المدمجة والسجل (Registry)

- **المدمجة** (`plugins/bundled.py`): ثمانية مصادر رسمية (MangaDex، WEBTOON، Tapas، 3asq، Hindawi،
  Gutenberg، arXiv، Standard Ebooks) من `backend/plugins/official/`. تُثبّت **مرة واحدة** لمكتبة جديدة عبر
  نفس مسار التثبيت، وعلامة دائمة في `app_meta` تمنع إعادة تثبيت مصدر حذفته. التحديث لا يوافق على
  صلاحيات جديدة تلقائيًا.
- **اللقطة المدمجة** تُحدَّث فقط بـ `python -m plugins.sync_snapshot --from <OneShelf-Adapters>`، ولا تُعدّل
  يدويًا.
- **السجل (Registry)**: فهرس JSON ثابت منشور من مستودع **OneShelf-Adapters** (فرع `registry`). الثقة:
  - السجل الأول (first-party) المحدد في `ONESHELF_FIRST_PARTY_REGISTRY_URL`: مستوياته (Official / Verified
    Community / Community) موثوقة كما هي.
  - أي سجل آخر: Community، إلا إذا وقّع الحزمة مفتاح Ed25519 موثوق في `ONESHELF_REGISTRY_TRUSTED_KEYS`.
  - المراجعة (`review-package`) تنزّل الحزمة وتتحقق من الـ hash وتشغّل اختباراتها **بدون تثبيت**، والتثبيت
    يمكن ربطه بـ sha256 المراجَع.
- تطوير المصادر الجديدة يتم في مستودع **OneShelf-Adapters**، الذي يستدعي `oneshelf.plugins.adapter_repo`
  من نسخة Core مثبتة، فيُحكم على أي مساهمة بنفس قواعد التثبيت بالضبط.

### 8.7 المولّد (`generator/`)

من رابط موقع: اكتشاف ساكن، ثم خريطة الموقع، ثم القدرات (مع تصعيد للمتصفح عند الحاجة)، ثم ثقة لكل قدرة
(Confirmed / Probable / Unknown / Unsupported). ينتج مسودة `.osp` مع fixtures حقيقية. التوليد لا يثبّت،
والتثبيت خطوة منفصلة بموافقة. «إصلاح إضافة» يبدأ بتشخيص ما انكسر، ثم يولّد نسخة جديدة مع diff للمحددات،
وتفعيلها يدوي.

## 9. الشبكة والمنظّم المروري

### 9.1 سياسة الخروج (`net/policy.py`, `net/http.py`) — حماية SSRF

كل خطوة (hop) تُفحص: الـ scheme، وعدم وجود بيانات اعتماد في الرابط، ورفض IP حرفي، والمنفذ، و**قائمة
النطاقات المسموحة للإضافة**. **كل إجابة DNS** تُفحص، وتُرفض كلها إذا كان أي عنوان غير عام (شبكات محلية
أو loopback). الاتصال يتم إلى العنوان المفحوص نفسه، فلا توجد نافذة DNS rebinding. التحويلات (redirects)
تُتبع يدويًا مع إعادة الفحص في كل مرة. لا proxy من البيئة، ولا تخزين تلقائي للكوكيز، والأجسام محدودة الحجم.

> الثقة الداخلية للشبكة المحلية (LAN) **لا توسّع** هذه السياسة أبدًا. إضافة لا تستطيع الوصول لجهاز في
> شبكتك.

### 9.2 المتصفح (`net/browser.py`, `net/egress_proxy.py`)

Chromium (Playwright) يبدأ فقط عند الحاجة (`LazyBrowser`). كل سياق له **وكيل خروج** خاص مربوط بسياسة
إضافة واحدة، وChromium ممنوع من الوصول لأي شيء مباشرة: لا DNS ذاتي، ولا QUIC، ولا WebRTC UDP، ولا تنزيلات،
ولا service workers. يُستخدم لاستخراج DOM، **وليس لقطات شاشة**.

### 9.3 المنظّم المروري (`net/governor.py`)

كل طلب لمصدر يأخذ «إيجارًا» (lease) من منظّم عام واحد. الأولويات:

| الأولوية | القيمة | أمثلة |
|---|---|---|
| `READER` | 1 | صفحة يقرأها المستخدم الآن |
| `INTERACTIVE` | 2 | بحث، فتح عمل |
| `MANUAL` | 3 | تنزيل طلبه المستخدم |
| `READ_AHEAD` | 4 | التحميل المسبق للقارئ، الأغلفة |
| `FOLLOW` | 5 | فحص المتابعات في الخلفية |
| `HEALTH` | 6 | فحوص الصحة |

- الترتيب: الأولوية، ثم المصدر الأقل خدمة (عدالة)، ثم الأقدم.
- الأعمال الخلفية (4 وما بعدها) **لا تأخذ آخر مقعد** HTTP أبدًا، وإيجارات المتصفح الخلفية تُلغى إذا احتاج
  القارئ أو المستخدم المتصفح.
- حدود لكل مصدر (افتراضيًا 2 متزامن)، ومسافة دنيا بين الطلبات، واحترام `Retry-After`.

## 10. البحث والاكتشاف

### 10.1 البحث (`search/service.py`, `api/discovery.py`)

**محلي أولًا ثم إثراء تدريجي:** `GET /api/search?q=` يبث SSE بالأحداث `local` ثم `partial` (مع كل مصدر)
ثم `complete`.
- النتائج المحلية من `search_index` (FTS5 + مرور substring محدود) تظهر فورًا ولا تُمسح أثناء عمل المصادر.
- كل مصدر له حالة خاصة (pending/cached/done/failed مع التصنيف) ويمكن إعادة محاولته وحده
  (`POST /api/search/retry`).
- **فلاتر النطاق** في نص البحث: `category:manga` و`lang:ar` (`features/search/scopes.ts`).
- لا يُكتب أي شيء عن الاستعلام في قاعدة البيانات، ولا يوجد سجل بحث.

**الترتيب** (`search/ranking.py`): طبقات صلة نصية (تطابق تام، ثم مطبّع، ثم تكافؤ عربي فضفاض...)، والمعززات
تعيد الترتيب داخل الطبقة فقط. البيانات الناقصة لا تخفض النتيجة أبدًا.

**تطبيع العربية** (`text/arabic.py`) للمفاتيح فقط وليس للعرض: إزالة التشكيل والتطويل، وتوحيد الألف، والألف
المقصورة إلى ياء، والأرقام الهندية إلى عربية. والوضع الفضفاض يضيف ة ↔ ه. بدون تجذيع (stemming).

### 10.2 التجميع والربط (`search/grouping.py`)

- `group_results()`: يعرض **عملًا منطقيًا واحدًا** لكل مجموعة نتائج متشابهة (Soft Group)، مع إبقاء كل
  مصدر قابلًا للاختيار. **لا يكتب شيئًا**.
- `persist_listing()`: عند فعل دائم (رف، متابعة، تنزيل، فتح) يربط Listing محددًا بمسار ويحترم قرارات الربط.
  نقطة الدخول من الواجهة: `POST /api/listings/bind` و`POST /api/listings/open`. مع `defer: true` يربط
  `open` القائمة ويعود فورًا: التفاصيل تُجلب في الخلفية ويُعلَن عنها بـ `work.changed`، والفهرس تطلبه صفحة
  العمل بنفسها.
- الأغلفة **للعرض فقط**، وليست دليل هوية أبدًا. والمتصفح لا يرى رابط المصدر، فكل غلاف يمر عبر
  `/api/covers` (بسياسة شبكة المصدر نفسه).

### 10.3 الكاش والرابط المباشر والرئيسية

- **كاش الاكتشاف** (`search/cache.py`، في `cache.db`): مفاتيح مُجزّأة (hashed) فقط، ومدة 7 أيام، وحد
  250MB، وLRU. لا يحمل أي حالة أساسية.
- **رابط مباشر** (`search/url_resolve.py`): يطابق الرابط مع `url_patterns` للإضافات المفعلة، ويستخدم
  قدراتها العادية.
- **الرئيسية** (`discovery/home.py`): Hero (متابعة القراءة، ثم مثبّت، ثم بيانات اكتشاف مخزنة، **بدون أي
  طلب شبكة**)، وTrending وLatest تظهر فقط إذا وفّرها مصدر فعلًا، وRecently Added هو المضاف حديثًا لرفّك.
- **استكشف** (`discovery/discover.py`, `api/discover.py`, ADR 0004): تصفّح قوائم المصدر نفسه («الأحدث» =
  `latest`، «الأشهر» = `trending`) صفحةً صفحة حتى 50، بترتيب المصدر دون أي تقييم من OneShelf، وكل نتيجة تقول إن
  كانت على رفّك. الصفحة المقروءة خلال 6 ساعات تأتي من الكاش، والأقدم تُطلب من جديد وتبقى احتياطًا إن فشل المصدر،
  والفشل بلا نسخة مخزنة يظهر `SOURCE_FAILED` لا قائمة فارغة. ومفاجأتان: **«فاجئني»** عمل عشوائي من أول صفحات
  قائمة عشوائية ليس على رفّك (6 صفحات كحد أقصى) مع ذكر المصدر والقائمة، و**«وش أقرأ من رفّي؟»** عمل على رفّك لم
  تبدأه ولم تكمله، بلا أي طلب شبكة.

## 11. ثقة الفهرس (الكتالوج)

`catalog/trust.py` — أساس المتابعة و«تنزيل الناقص» وكل استنتاج حذف:

- **لقطة كاملة فقط** تصبح Trusted. الفهرس غير المكتمل (ترقيم لم ينتهِ، طلب فشل) يُسجّل كدليل، لكنه لا يحل
  محل الموثوق ولا يُستخدم للمتابعة.
- **Suspicious**: فقدان مفاجئ لنحو 50% أو أكثر، وعلى الأقل 5 وحدات. لا يحل محل الموثوق إلا بعد **فحصين
  كاملين متتاليين متفقين**، أو بضغط المستخدم «Trust This Catalog».
- الوحدة التي تختفي من المصدر **يبقى ملفها** ولا تُعتبر محذوفة.
- العمل المكتمل يبقى مكتملًا، ويظهر «3 إصدارات منذ الإكمال».

نقاط النهاية: `GET /api/tracks/{id}/catalog`، و`POST .../catalog/refresh`، و`POST .../catalog/trust`.

## 12. محرك التنزيل

`downloads/engine.py` + `downloads/contract.py` + `downloads/runner.py`

### 12.1 عقد الاستخراج (Extraction Contract)

كل مهمة لها عقد ثابت: **المصدر + اللغة + الوحدة + الصيغة المطلوبة + الطريقة**. الاحتياط (fallback) يغيّر
**الطريقة فقط**.

- **الطرق:** `direct` (ملف من وصفة `downloads`)، و`html_api` (عبر وصفة `reader`)، و`reader_media`،
  و`browser`.
- **أولوية اختيار الطريقة:** مرة واحدة، ثم إعداد المصدر، ثم الإعداد العام، ثم توصية الإضافة
  (`resolve_method`).
- **الصيغة المطلوبة** (`required_output`):
  - قارئ نصي → `text` (`.ostext`).
  - `direct`، أو مصدر بلا قارئ، أو مصدر عنده قارئ وملفات والعمل كتاب → `file` (يُحفظ الملف الأصلي:
    pdf/epub/cbz).
  - غير ذلك → `cbz` (تُجمّع صور الصفحات).
- **مصدر الموارد** (`_resources`): وصفة `downloads` عندما تكون الطريقة `direct` **أو عندما يكون العقد يطلب
  ملفًا والمصدر يقدّم ملفات**. غير ذلك وصفة `reader`. (القاعدة الثانية أُصلحت في 2026-11: كان الكتاب من
  مصدر يجمع قارئًا وملفات يُحمَّل كصورة ويُرفض.)

### 12.2 الحالات

```
QUEUED → PREPARING → DOWNLOADING → VERIFYING → PACKAGING → COMMITTING → COMPLETED
                ↘ RETRY_WAIT / WAITING_FOR_RATE_LIMIT / WAITING_FOR_SESSION ↗
                ↘ FAILED  ·  CANCELED  ·  RECOVERING (بعد إعادة تشغيل)
```

الدفعة (`download_batches`) تجمع مهام لكل وحدة، وفشل وحدة لا يُفشل الدفعة كلها. حالة الدفعة المحسوبة:
`active, paused, completed, completed_with_issues, failed, canceled`.

### 12.3 خط المعالجة (`_process`)

1. اختيار موقع التخزين (المحدد أو الافتراضي)، والتحقق من توفره، و**فحص المساحة** مقابل الاحتياطي.
2. إنشاء منطقة staging قابلة للاستئناف داخل نفس موقع التخزين: `<root>/.oneshelf/staging/<id>/`.
3. جلب قائمة الموارد من المصدر.
4. حسب الصيغة:
   - **CBZ:** تنزيل كل صفحة إلى `NNNN.img.part`، ثم فحصها كصورة، ثم إعادة تسميتها، وتسجيل sha256 في
     `manifest_json`. الاستئناف يتخطى الصفحات المتطابقة. بعدها تجميع ZIP مع `ComicInfo.xml`، ثم التحقق.
   - **نص:** تنقية الأقسام وكتابة الحاوية والتحقق.
   - **ملف:** تنزيل متدفق مع **استئناف** بـ ETag/Last-Modified، وفحص المساحة مقابل الحجم المعلن، ثم التحقق.
     الملف السيئ يُحذف وتبدأ المحاولة التالية من الصفر.
5. **الالتزام** عبر سجل الالتزام (§13.4)، ثم تسجيل الـ asset، وإضافة العمل للرف تلقائيًا، وكتابة السجل.

### 12.4 إعادة المحاولة والاحتياط (`next_method`)

- أخطاء نهائية (`source_unlinked, too_large, format_unavailable`): تفشل فورًا.
- `auth_failure`: انتظار الجلسة (`WAITING_FOR_SESSION`). `rate_limit`: انتظار.
- غير ذلك: إعادة محاولة بنفس الطريقة حتى 3 مرات مع backoff أُسّي (2، 4، 8 ثوانٍ...).
- بعدها، إذا كان الخطأ «خاصًا بالطريقة» (parser/selector/media_invalid/not_found...): في وضع
  `preferred_ask` الافتراضي **يسأل المستخدم**، وفي `automatic` ينتقل للطريقة التالية في الترتيب المحدد، وفي
  `strict` يفشل.
- الإشعار يكون عند **الفشل النهائي فقط**.

### 12.5 أشياء مهمة

- الوحدة التي لها نسخة سليمة لا تُنزّل مرة ثانية (`skipped: already_downloaded`). ونسخة اختفى ملفها من موقع
  موصول تُعلَّم `missing_local_file` وتُستبدل.
- «إصلاح» (`repair: true`) هو نفس خط التنزيل بالضبط، والنسخة المكسورة لا تُستبدل إلا بعد التحقق من الجديدة.
- `DownloadRunner` يدوّر `run_once` في الخلفية. والإلغاء يحذف الجزئي افتراضيًا.
- **التنزيل التلقائي أثناء القراءة** مطفأ افتراضيًا. إذا فُعّل، يبدأ عند نحو 12% من الوحدة مع تفاعل حقيقي،
  ويمكن أن ينزّل الوحدات الخمس التالية، وتُلغى المهام التي لم تبدأ عند مغادرة العمل.
- **المتابعة لا تنزّل أبدًا** تلقائيًا.

نقاط النهاية: `POST /api/downloads {unit_ids, root_id?, repair?, formats?}`، و`GET /api/downloads[/{batch}]`،
و`POST /api/downloads/{batch}/{pause|resume|retry-failed|cancel|reorder}`،
و`POST /api/downloads/jobs/{job}/{retry|cancel}`، و`GET /api/downloads/jobs/{job}/file` (حفظ الملف)،
و`DELETE /api/downloads/history` (يمسح السجل فقط، لا المحتوى).

## 13. التخزين

### 13.1 مواقع التخزين (`storage/roots.py`)

موقع التخزين (storage root) مجلد مسجّل بمعرّف ثابت، ومعه **ملف علامة** داخله (`.oneshelf/`). إذا غابت
العلامة أو كانت لموقع آخر، يُعتبر الموقع **غير متاح** (مثلًا قرص غير موصول)، ولا يُعتبر المحتوى محذوفًا.
واحد منها هو الافتراضي للتنزيلات. **لا يمكن التنزيل قبل وجود موقع تخزين** (`NoStorageLocation`).

### 13.2 التخطيط (`storage/layout.py`)

```
<root>/<Family>/<Work Title> [<work_id>]/<language>/<source_id>/<Unit Label> [<unit_id>].<ext>
Family = Sequential Art (manga/manhwa/manhua/comic) | Books (book/novel/paper) | Other
```

المعرفات القصيرة داخل الأسماء تمنع التصادم وتسمح باسترداد الملفات بعد نقلها يدويًا. **تغيير البيانات لا
يعيد تسمية الملفات الموجودة.**

### 13.3 أمان المسارات (`storage/paths.py`)

أي اسم من مصدر أو ملف مستورد غير موثوق. `safe_component()` هي الوحيدة التي تحوّل اسمًا إلى مكوّن مسار، و
`resolve_within()` ترفض أي هروب خارج الموقع، بما في ذلك عبر symlink. و`delete_managed_file()` لا تحذف إلا
ملفًا عاديًا داخل الموقع.

### 13.4 سجل الالتزام (`storage/commit.py`) — الكتابة الآمنة من الانهيار

SQLite ونظام الملفات ليسا معاملة ذرية واحدة، فكل التزام يمر بحالات محفوظة:

```
pending → moved → verified → registered → done    (أو aborted)
```

كل خطوة قابلة لإعادة التشغيل بعد انهيار، وتُستكمل عند الإقلاع. لا يُسجّل إلا ملف نهائي تم التحقق منه، ولا
يُكتب فوق ملف موجود أبدًا. و`fsync` للملف وللمجلد بعد النقل لضمان الثبات (على ويندوز لا يدعم النظام fsync
للمجلدات، فيتخطاه الكود هناك).

### 13.5 الحماية من امتلاء القرص

الاحتياطي = 5% من حجم الموقع بحد أقصى 5GB، والتحذير عند ضعف ذلك. كل تنزيل يفحص المساحة قبل البدء، وقبل
الملف الكبير يفحصها مقابل حجمه المعلن.

### 13.6 الماسح والترحيل وتنظيف staging

- **الماسح** (`storage/scanner.py`): لا يحذف سجلات أبدًا. ملف حُذف يدويًا يصبح `missing_local_file`، وملف
  نُقل داخل الموقع يُسترد بالمعرف المضمّن في اسمه مع تطابق checksum.
- **الترحيل** (`storage/migration.py`): فحص، ثم نسخ، ثم تحقق checksum، ثم تبديل، ثم مطابقة، وقابل للاستئناف.
  **النسخة القديمة تبقى** حتى يحذفها المستخدم صراحة. أما تغيير مسار التركيب فقط فهو «remap» وليس ترحيلًا.
- **تنظيف staging** (`storage/staging_cleanup.py`): بقايا النجاح بعد نحو 24 ساعة، والأجزاء القابلة للاستئناف بعد
  نحو 7 أيام، وفقط ما ثبت يُتمه.

## 14. القارئ

### 14.1 اختيار القارئ (`frontend/src/features/reader/ReadRoute.tsx`)

`GET /api/reader/units/{id}/context` يرجع `kind` والصيغ المحلية المتوفرة، ثم:

| الحالة | القارئ |
|---|---|
| ملف `epub` أو `pdf` محلي | `BookReader` (‏EPUB عبر `epub.ts` ‏/ PDF عبر pdf.js في `PdfView.tsx`) |
| وحدة نصية (`text`) | `BookReader` بصيغة text |
| مصدر ملفات فقط ولم يُنزّل | `DownloadToRead` (يعرض حالة التنزيل وزرّه) |
| مصدر لا يسمح بالقراءة ولا التنزيل | «افتحه على موقع المصدر» |
| غير ذلك (صور صفحات) | `ReaderScreen` (قارئ الصفحات) |

### 14.2 قارئ الصفحات (`ReaderScreen.tsx`)

- الأوضاع: `long_strip` (تمرير عمودي)، و`single`، و`double`. الاتجاه: ltr/rtl/vertical. الملاءمة:
  `smart` (عرض حتى 900px)، و`width`، و`height`، و`original`. مع تكبير وسحب ونقر مزدوج.
- **الأداء:** في الوضع الطويل لا يُركّب إلا نطاق محدود (4 قبل + الحالية + 15 بعد)، والباقي spacers بارتفاع
  تقديري.
- **التحميل المسبق** (`pagePreloads.ts`): `PagePreloads` يجلب الصفحات التالية بـ 3 طلبات متوازية إلى blob
  URLs، ويحترم `Retry-After` بإيقاف مؤقت.
- **رؤوس الكاش حسب الأصل** (`api/library.py`): `X-OneShelf-Origin` = `local` (‏7 أيام immutable) أو
  `cache` (يوم) أو `online` (ساعة).
- **مقياس الملاءمة** مضبوط على الإطار `.reader__frame` نفسه (`styles/reader.css`)، لأن الصورة داخل إطار
  ينكمش لحجمها كانت تبقى بحجمها الطبيعي. (أُصلح في 2026-11.)
- **الشريط العلوي:** صف واحد (رجوع، العنوان والفصل، المحتويات، الإعدادات، ملء الشاشة، المزيد). تحت 900px
  يصير أيقونات فقط، وملء الشاشة والمصدر وحالة التنزيل تنتقل إلى «المزيد».
- **الشريط السفلي:** الفصل السابق، العداد (معزول LTR فيظهر «1 / 3» صحيحًا بالعربي)، scrubber عريض باتجاه
  الكتاب، الفصل التالي (بترتيب المصدر).
- الأشرطة المخفية `inert` فلا يصلها Tab، والتركيز يُظهرها. ووضع «Minimal» يخفيها حتى تُستدعى.
- **اللمس:** الثلث الأيمن والأيسر يقلبان الصفحة حسب اتجاه الكتاب، والوسط يُظهر الأشرطة أو يخفيها (انتظار
  240ms حتى يبقى النقر المزدوج للتكبير). تلميح يظهر مرة واحدة.
- **المفاتيح:** الأسهم حسب الاتجاه، Space، وHome/End، وShift+F لملء الشاشة، وEsc. مستمع لوحة مفاتيح
  واحد طوال عمر القارئ يستدعي أحدث معالج، ولا يُعاد ربطه مع كل render.
- **نهاية الفصل:** بطاقة «أنهيت هذا الفصل» مع زر كبير «اقرأ التالي: …» يأخذ التركيز، والفصل يُعلَّم مقروءًا،
  وأول ثلاث صفحات من الفصل التالي تُجلب مسبقًا قرب النهاية.
- لوحات الإعدادات والمحتويات بألوان القارئ (أسود/رمادي/أبيض)، والخيارات أدوات segmented.

### 14.3 مصدر الصفحة على الخادم (`reader/service.py` → `page()`)

1. إذا وُجد **ملف CBZ محلي** سليم: تُقرأ الصفحة من داخل الأرشيف (`origin: local`).
2. غير ذلك، قائمة الصفحات من المصدر (مع ذاكرة محدودة 256 وحدة لمدة 30 دقيقة، وكاش دائم في `cache.db`).
3. إذا كانت الصفحة في **كاش القارئ** (7 أيام، 5GB، LRU، لا يطرد الوحدة المفتوحة): `origin: cache`.
4. غير ذلك جلب أونلاين بأولوية READER، مع دمج الطلبات المتكررة لنفس الصفحة، وتجديد الروابط المنتهية
   (403/404 تعني «اطلب القائمة من جديد مرة واحدة»)، ثم تطبيع الصورة (SVG يُحوَّل بأمان)، ثم التحقق والتخزين في
   الكاش (`origin: online`).

### 14.4 التقدّم والعلامات

- `reading_state` فيه `revision` يزيد مع كل كتابة. الكتابة بنسخة قديمة ترجع **409**، فتبويب قديم لا يرجع
  التقدّم للوراء.
- التعليم كمقروء تلقائيًا عند 97%.
- العلامات المرجعية والتظليل لها `operation_id` لمنع التكرار عند إعادة الإرسال.
- «مصدر بديل» (`reader/alternatives.py`): يقترح نفس الوحدة من مصدر آخر **بنفس اللغة** فقط وبنفس الرقم
  والنوع، وإذا لم يكن هناك مرشح واحد واضح لا يخمّن.

## 15. الرف، المتابعة، الإشعارات، صحة المصادر

### 15.1 الرف (`library/shelf.py`, `api/shelf.py`)

- **العروض (views):** `all, saved` (لم تُقرأ)، و`reading`، و`completed`، و`favorites`، و`pinned`،
  و`downloaded` (فيه ملف سليم). والبحث داخل الرف محلي فقط (`?q=`).
- كل مدخل يحمل: `content_type`، و`read_fraction`، و`last_read_at`، و`total_bytes`، و`downloaded_units`،
  و`releases_since_completion`، و`cover_url`.
- **الاستقلال:** الإزالة من الرف لا تلغي المتابعة ولا تحذف الملفات إلا إذا طُلب. وحذف الملفات يُبقي الرف
  والمتابعة والتقدّم.
- **حذف التنزيلات بسهولة:**
  - `DELETE /api/units/{unit}/files`: ملفات فصل واحد.
  - `DELETE /api/works/{work}/files`: كل ملفات العمل.
  - `POST /api/shelf/batch {action: "delete_files", work_ids}`: عدة أعمال دفعة واحدة.
  - كلها ترجع `deleted_files` و`freed_bytes`. والملف الذي ترفضه طبقة الأمان (symlink مثلًا) يبقى ولا يُحسب.
  - في الواجهة: شريط المساحة وزر الحذف السريع في «رفّي ← المحمّلة»، وزر لكل فصل محمّل وآخر للعمل كامل في
    صفحة العمل، وزر لكل ملف في صفحة التنزيلات. كلها عبر `features/files/useFileDeletion.tsx`.
- الوسوم والمجموعات والملاحظات والتقييم: `api/tags.py` (`/api/tags`، `/api/collections`،
  `/api/works/{id}/notes`).
- العمليات الجماعية: `favorite, unfavorite, complete, uncomplete, remove, delete_files`.

### 15.2 المتابعة (`follow/`)

- المتابعة = عمل + لغة + مصدر مفضّل + مسار. يُحفظ **خط أساس** من الفهرس الموثوق.
- الاكتشاف يقارن آخر فهرس **موثوق** بخط الأساس، **وليس** «أكبر رقم» ولا الفجوات الرقمية. تغيّر البيانات
  وإعادة الترتيب واختفاء وحدة ثم عودتها **ليست** إصدارات جديدة.
- `FollowRunner` يفحص المستحق كل 12 ساعة تقريبًا مع jitter، مجمّعًا حسب المصدر، وبأولوية FOLLOW.
- إلغاء المتابعة فوري مع **تراجع** (`undo_token`).
- الحالات: `up_to_date, new_releases, degraded, catalog_suspicious, reconnect_required, checking`.

### 15.3 الإشعارات (`notifications/service.py`)

- **مفتاح dedupe إلزامي:** مشكلة منطقية واحدة = إشعار واحد يُحدَّث.
- فئتان: `important` (تظهر في «يحتاج انتباهك»: إعادة اتصال، تخزين منخفض أو غير متاح، فهرس مشبوه...)
  و`informational`.
- «تمت المشاهدة» **لا يغيّر** حالة القراءة أبدًا. والمحلول يبقى نحو ساعة، والسجل 30 يومًا أو 500 مدخل.
- لا إشعارات متصفح في الإصدار الأول.

### 15.4 صحة المصادر (`sources/health.py`, `health/service.py`)

إشارات سلبية من كل استخدام حقيقي (نجاح/فشل لكل قدرة) تُفسَّر بعتبات وhysteresis. «Rate Limited» و
«Reconnect Required» حالات مستقلة، وعنصر مفقود واحد لا يُضعف المصدر، والتعافي يحتاج نجاحًا متكررًا. **الصحة
تصف فقط**، ولا تغيّر الطريقة ولا المصدر ولا اللغة أبدًا.

## 16. الاستيراد، النسخ الاحتياطي، الاستعادة، التصدير

### 16.1 الاستيراد (`importer/`)

`POST /api/import/uploads?filename=` (مراجعة: الصيغة، الصفحات، اقتراحات الربط)، ثم `POST /api/import`.
المسار: كشف الصيغة من المحتوى، ثم الهدف (اختر عملًا أو أنشئ عملًا محليًا، ولا دمج عدواني أبدًا)، ثم فحص
المساحة، ثم نسخ إلى staging، ثم التحقق، ثم الالتزام. في وضع **Move** لا يُحذف الأصل إلا بعد اكتمال الالتزام
وبشرط أنه لم يتغير.

### 16.2 النسخ الاحتياطي (`backup/`)

- **Library Backup** (الحالة والبيانات بدون الملفات): تلقائية كل 7 أيام، ويُحتفظ بآخر 4 نسخ تم التحقق منها.
- **Full Backup** (مع ملفات أعمال تختارها): يدوية.
- قاعدة البيانات تُلتقط بـ online backup API.
- **مستثنى دائمًا:** الجلسات والرموز والمفاتيح وملفات تعريف المتصفح وstaging والأجزاء والكاش.
- تحذير إذا كانت النسخ على نفس قرص المكتبة.

### 16.3 الاستعادة (`restore/`)

فحص مسبق (التوافق، والإضافات، والصلاحيات)، ثم ترحيل قاعدة النسخة **داخل نسخة staging** (ملف النسخة لا
يُعدّل). النسخة الأحدث من التطبيق تُرفض.
- **Replace:** يأخذ «لقطة أمان» أولًا.
- **Merge:** تعديلاتك وقرارات الربط والإعدادات الحالية تغلب، والسجلات الناقصة تُضاف، **والتقدّم لا يتراجع
  أبدًا**، والملفات السليمة لا تُستبدل، وملفات النسخة الموثّقة يمكن أن تصلح الملفات المفقودة أو التالفة.

### 16.4 التصدير (`export/`)

نسخة **باتجاه واحد** محمولة ولا تعدّل المكتبة أبدًا. تفضّل الأصول المحلية، و**لا تحوّل الصيغ**. للمحتوى
الناقص ثلاثة خيارات، و«نزّل الناقص ثم صدّر» يتطلب إشعارًا صريحًا بأنه سيُنزَّل للمكتبة نهائيًا. قابل
للاستئناف، وتعارض الأسماء يُعالج حسب اختيارك.

  و`follow.changed`، و`follow.releases`، و`shelf.changed`، و`source.session`، و`source.health`،
  و`task.finished`، و`work.changed` (وصلت تفاصيل عمل فُتح مؤجَّلًا).
- **الواجهة:** `app/live.tsx` → `LiveProvider` بث واحد للتطبيق كله. وإذا انقطع البث تتحول الشاشات المشتركة إلى
  polling كل 15 ثانية تلقائيًا. والشاشة تستخدم `useLive([...events], reload)`، والحدث يعني «أعد القراءة»
  فقط ولا يحمل حالة.
- صفحة العمل تجمع أحداث `download.job` المتتالية في إعادة قراءة واحدة كل 800ms، فتتحول الفصول إلى «محمّل»
  وهي تكتمل.

### 18.3 الأنماط الأساسية

- **جلب البيانات:** `useResource<T>(path, query)` يرجع `{data, error, loading, reload}`، ويحفظ البيانات
  القديمة أثناء إعادة التحميل لنفس المسار.
- **التعديل:** `api.post/put/delete` يرمي `ApiError(status, code, message)` برسالة مفهومة للإنسان من الخادم.
- **الترجمة:** كل نص في `i18n/strings.ts` بمفتاح موحّد للغتين. ونوع `StringKey` مشتق من مفاتيح الإنجليزية،
  فالمفتاح الناقص خطأ TypeScript. استخدم `t("key", {var})`. الاتجاه (`dir`) و`lang` يُضبطان على `<html>`.
- **RTL:** استخدم الخصائص المنطقية (`inline-start/end`، `margin-inline`...). للقيم اليسارية داخل جملة عربية
  (أحجام، روابط) استخدم `<bdi>` أو `isolate()`. والعناوين بلغة مختلفة لها `dir="auto"`، ومحاذاتها تتبع الصفحة.
- **الهوية البصرية:** أخضر غابة داكن للشريط الجانبي، وعاجي دافئ للوحة، وزيتوني خافت للتمييز، وخشب طبيعي
  للرفوف، وعناوين بخط serif أدبي (Noto Serif / Noto Naskh Arabic). الألوان في `tokens.css` مع نسخة داكنة.
  القارئ استثناء: أسود/رمادي/أبيض فقط.
- **الحذف والأفعال الخطرة:** `ConfirmDialog` مع `danger`، والنص يقول **ما سيُحذف وما سيبقى** (ليس «هل أنت
  متأكد؟» فقط). النص مربوط بالنافذة (`aria-describedby`)، والتركيز يبدأ على «إلغاء» في الأفعال الخطرة.
- **نظام التصميم (`tokens.css`):**
  - ألوان دلالية بنسختين فاتحة وداكنة: `--control-border` (حواف الأزرار والحقول، تباين 3:1 على الأقل)،
    و`--focus-ring`، و`--progress-fill`، و`--danger/warning/success/info-{surface,border}` مع
    `--danger-text`، و`--on-danger`، و`--scrim`، و`--shadow-overlay`.
  - مقياس خطوط: `--text-xs` (12، الحد الأدنى) إلى `--text-display`.
  - طبقات `--z-*`.
  - لا تكتب لونًا خامًا (hex) في قاعدة جديدة: استعمل token حتى يعمل الوضع الداكن.
- **حالات الاختيار:** لغة واحدة. الـ chip أو التبويب أو مبدّل العرض المختار يُملأ بالأخضر الغابي. وزر الفعل
  المضغوط (متابعة، اكتمل) يأخذ خلفية success خفيفة.
- **الإشعارات النصية:** `.notice--problem | --warning | --success | --info`.
- **التحميل:** `LoadingState variant="shelf" | "rows" | "line"` يرسم شكل المحتوى القادم. ويظهر فقط في أول
  تحميل (`loading && data === null`)، فالتحديث الحي لا يُفرغ الشاشة.
- **الحركة:** `MotionConfig reducedMotion="user"` حول التطبيق كله، و`scroll-behavior` يتوقف مع تقليل الحركة.
- **النصوص:** مصطلحات موحّدة (فصل، تنزيل/منزَّل، مصدر، قائمة الفصول، رفّي = شاشة الرف فقط). والجمع عبر
  `tn(baseKey, count, values)` بقواعد `Intl.PluralRules`، والمفاتيح `base.zero|one|two|few|many|other`.
  والأخطاء عبر `errorText(error)` الذي يحوّل كل كود خطأ من الخادم إلى جملة باللغتين.
- **الحركة:** `motion` مع `useReducedMotion()`. احترم تقليل الحركة دائمًا.
- **التنقل:** شريط جانبي على سطح المكتب، و4 وجهات (الرئيسية، البحث، استكشف، رفّي) + «المزيد» في الأسفل على
  الجوال، و«المتابعة» داخل «المزيد» (`navigation.ts`،
  `mobile: true/false`). تغيير الصفحة يرجع لأعلى وينقل التركيز لـ `<main>` (عدا أول تحميل، ليبقى رابط
  «تخطَّ إلى المحتوى» أول ما يصل له المستخدم بلوحة المفاتيح).

## 20. الثوابت التي لا تُكسر

أي تعديل يجب أن يحافظ على هذه. لكل واحد اختبارات تحرسه:

1. فهرس مشبوه أو غير مكتمل لا يمسح الحالة الموثوقة أبدًا.
2. لا تبديل صامت للمصدر أو اللغة.
3. التجميع الناعم (Soft Group) لا يصبح هوية دائمة لمجرد تشابه العناوين.
4. تحديث المصدر لا يكتب فوق تصحيحات المستخدم بصمت.
5. البيانات غير المعروفة ليست دليلًا سلبيًا.
6. الجودة غير المعروفة لا تحجب المحتوى.
7. القراءة لا تعني تنزيلًا دائمًا إلا إذا فعّل المستخدم التنزيل التلقائي.
8. التنزيل التلقائي مطفأ افتراضيًا.
9. المتابعة لا تنزّل الإصدارات الجديدة تلقائيًا.
10. الإزالة من الرف، وإلغاء المتابعة، وحذف الملفات أفعال مستقلة.
11. المحتوى المحلي يُقرأ بدون مصدر أو إضافة أو شبكة.
12. محتوى القارئ لا يستطيع تنفيذ أفعال مميزة في OneShelf.
13. الإضافات المجتمعية لا تنفّذ كودًا.
14. الإضافات لا تصل لمسارات ملفات عشوائية.
15. الإضافات لا تصل للشبكة المحلية أو الخدمات الداخلية (SSRF).
16. التنزيل غير المكتمل لا يظهر كمحتوى مكتمل في الرف.
17. الانهيار أثناء الالتزام قابل للاسترداد بشكل idempotent.
18. التخزين غير الموصول لا يُعامل كحذف جماعي.
19. النسخ الاحتياطي لا يحتوي جلسات أو كلمات مرور أو رموزًا.
20. التصدير لا يعدّل المكتبة.
21. «نزّل الناقص ثم صدّر» يتطلب إشعارًا صريحًا.
22. الإشعارات لا تغيّر حالة القراءة.
23. مسح السجل لا يحذف المحتوى ولا الحالة.
24. التنقل في القارئ يتبع ترتيب المسار، وليس افتراضات رقمية.
25. نقل التقدّم بين المصادر تقريبي ويدوي، وليس تطابق صفحات مزيّف.
26. عمل المتصفح الخلفي لا يجوّع القارئ أو المستخدم.
27. نتائج البحث تمثل أعمالًا، وليس بطاقات مكررة لكل مصدر.
28. الأغلفة للعرض فقط، وليست دليل هوية.
29. تشخيص المطابقة لا يصبح telemetry.
30. الوصول البعيد بـ passkey/جلسة/CSRF، والشبكة المحلية الحقيقية موثوقة حسب الإعداد.

## 23. وصفات تعديل شائعة

### إضافة نص للواجهة
أضف المفتاح في `frontend/src/i18n/strings.ts` في قسم `en` **وفي** قسم `ar`، ثم استخدم `t("key")`. المفتاح
الموجود في `en` فقط يعرض الإنجليزية في العربي، والمفتاح غير الموجود في `en` خطأ نوع.

### إضافة شاشة
1. أنشئ `features/<area>/<Name>Screen.tsx`.
2. أضف المسار في `app/routes.tsx` (استخدم `lazy` إن لم تكن يومية).
3. إن كانت وجهة رئيسية أضفها في `app/navigation.ts` (مع `mobile`) وأيقونتها في `components/Icon.tsx`.
4. أضف النصوص، واختبارًا في `<Name>Screen.test.tsx`.

### إضافة نقطة API
1. أضف الدالة في الخدمة المناسبة (المنطق هنا وليس في الـ router).
2. أضف الـ route في `api/<area>.py`. الأخطاء بـ `error(status, "CODE", "رسالة لإنسان")`. انتبه للترتيب: المسارات
   الثابتة مثل `/shelf/batch` قبل `/shelf/{work_id}`.
3. اختبار تكامل في `backend/tests/integration/` باستخدام `TestClient`.
4. حدّث `docs/api.md` وهذا المرجع.

### تغيير مخطط قاعدة البيانات
أضف ملفًا جديدًا `backend/oneshelf/db/schema/NNNN_name.sql` برقم أكبر. **لا تعدّل ترحيلًا قديمًا أبدًا.**
تغيير جدول بقيود يتم بإنشاء `<table>_new` ونسخ البيانات وإعادة التسمية داخل الترحيل (انظر 0017 و0020).

### إضافة إعداد
القيمة الافتراضية في `settings/defaults.py`، والتخزين عبر `Settings(conn).set/get(scope, scope_id, key, …)`،
والواجهة في `features/settings/*Panel.tsx`.

### إضافة عرض للرف
أضف الاسم إلى `VIEWS` وشرطه SQL في `library/shelf.py → view()`، ثم إلى `VIEWS` في `ShelfScreen.tsx` مع نصه.

### إضافة مصدر جديد
لا يتم في هذا المستودع: يُطوَّر في **OneShelf-Adapters** ويصل عبر السجل. أو جرّبه محليًا بالمولّد
(الإعدادات ← مطوّر) أو برفع `.osp` من شاشة المصادر.

### تغيير الهوية البصرية
الألوان في `styles/tokens.css` (فاتح وداكن). الرفوف والبطاقات في `library.css`. والقارئ في `reader.css`
فقط. لا تكسر الخصائص المنطقية للـ RTL.

## 24. مشاكل معروفة وملاحظات

- **ويندوز للتطوير:** كان الالتزام يفشل بـ `Bad file descriptor` لأن ويندوز لا يدعم `fsync` لمجلد ولا لملف
  مفتوح للقراءة فقط. `storage/safe_write.py` (`fsync_dir`، `sync_file`) يتعامل مع ذلك الآن. والإنتاج على
  Linux لم يتأثر.
- **كاش المتصفح للصفحات:** صفحة قُرئت أونلاين تبقى في كاش المتصفح ساعة واحدة. بعد التنزيل قد يرى المتصفح
  النسخة الأونلاين المخزنة لنفس الصفحة، والمحتوى نفسه في الحالتين.
- **مصادر مثبتة من السجل أو الرفع** لا تتحدث بتحديث اللقطة المدمجة، وتحديثها يكون من السجل أو برفع
  الحزمة الجديدة.
- **`update.sh` يرفض** إذا كانت هناك تعديلات غير محفوظة على ملفات متتبَّعة في نسخة الخادم.
- **النشر:** خذ نسخة من قاعدة البيانات قبل أي تحديث، فالترحيلات أمامية فقط، ولا ترجع لنسخة كود أقدم على
  قاعدة بيانات أحدث.
- **سجل المصادر القديم** (`registry/` في هذا المستودع) أُزيل. والحاوية تحوّل الرابط القديم
  `.../IPurplel/OneShelf/main/registry/index.json` تلقائيًا إلى سجل OneShelf-Adapters.
