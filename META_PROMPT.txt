1.3 THE ADAPTER CONTRACT (app/adapters/base.py)

    class Adapter(ABC):
        id / name / priority / owns_its_host / right_to_left
        content_type: "manga" | "comics" | "book"     <- REQUIRED, a test enforces
        packaging:    "cbz" | "file" | "pdf" | "text"
        matches(url, html) -> bool                    <- classmethod, abstract
        fetch_series(url) -> Series                   <- abstract
        fetch_chapters(series) -> list[Chapter]       <- abstract
        fetch_pages(chapter) -> list[Page]            <- abstract
        fetch_text(chapter) -> TextChapter            <- for packaging == "text"
        search(site, query, limit) -> list[SearchResult]   <- default returns []
        packaging_for(chapter) -> str                 <- per-chapter override
        transform_page(bytes) -> bytes                <- unwrap before validation
        pages_expire / refresh_pages(chapter)         <- for expiring page URLs

    Adapters are chosen by DOM FINGERPRINT, not hostname (registry.resolve).
    This is why 3asq, arabtoons and rizzfables needed zero lines of code.
    REMEMBER THIS. It is the cheapest coverage in the whole program.

1.6 ROOT CAUSE — Arabic search. FOUNDATION IS GOOD; THREE GAPS.

    app/adapters/textmatch.py ALREADY implements Lucene ArabicNormalizer rules
    (textmatch.py:44) and it is wired into base._normalise -> _score ->
    relevance / query_matches, and into main._identity_key:

        NFKD -> drop combining marks (harakat + Latin accents)
        alef forms   A/'A/'I/madda/wasla -> bare alef
        alef maqsura -> yeh          teh marbuta -> heh
        tatweel U+0640 stripped      Arabic-Indic digits -> ASCII
        apostrophes deleted, casefold, \W+ -> single space

    CODEPOINT REFERENCE. Work from this, not from prose descriptions — several
    of these letters are visually near-identical and a paste can carry either.

      ALREADY FOLDED (in _ARABIC_FOLD or via the NFKD + combining-mark strip):
        U+0622 alef madda      U+0623 alef hamza above   U+0625 alef hamza below
        U+0671 alef wasla        ... all four -> U+0627 bare alef
        U+0649 alef maksura   -> U+064A yeh
        U+0629 teh marbuta    -> U+0647 heh
        U+0640 tatweel        -> deleted
        U+0660-U+0669 and U+06F0-U+06F9 digits -> ASCII 0-9
        U+064B-U+0652 harakat (tanween, fatha, damma, kasra, shadda, sukun)
        U+0670 superscript alef      ... removed by the combining-mark strip
        Presentation forms U+FB50-U+FDFF and U+FE70-U+FEFF are handled by the
        NFKD pass. Do not add them by hand.

      GAP C — NOT FOLDED TODAY, AND SHOULD BE (verify against live titles):
        U+06A9 keheh          -> U+0643 kaf     (Persian/Urdu keyboards)
        U+06CC farsi yeh      -> U+064A yeh     (very common in scraped titles)
        U+06C0 heh with yeh   -> U+0647 heh
        U+06D5 ae             -> U+0647 heh

      DELIBERATELY NOT FOLDED — leave alone without measured evidence:
        U+0624 waw with hamza        U+0626 yeh with hamza
        Lucene does not fold these either; folding them conflates more
        aggressively than the measured evidence justifies.

      GAP B — STRIP THESE FROM THE QUERY BEFORE FOLDING:
        U+200B ZWSP    U+200C ZWNJ   U+200D ZWJ    U+FEFF ZWNBSP/BOM
        U+200E LRM     U+200F RLM    U+061C ALM    <- U+061C is easy to miss
        U+202A-U+202E  embedding and override controls
        U+2066-U+2069  isolate controls
      Today these hit the \W+ rule inside fold() and become SPACES, splitting
      one word into two tokens. Copy-pasting a title from a browser or a PDF
      routinely carries them, and the user never sees them.

    Do NOT rewrite this module. Extend it. The gaps are:

    GAP A — THE QUERY SENT TO EACH SITE IS NEVER NORMALIZED.
        app/main.py:525 is `query = q.strip()` and nothing else. Folding runs
        only on results COMING BACK. A site whose own index is un-normalized
        still misses, and we never see the hit at all — nothing to re-rank.
        This is the most likely cause of the reported Arabic failure and the
        most valuable thing in WP-3.

    GAP B — NO BIDI / ZERO-WIDTH HANDLING ON THE QUERY.
        U+200E/200F (LRM/RLM), U+202A-202E (embedding/override), U+200C/200D
        (ZWNJ/ZWJ) survive .trim(). Inside fold() they hit the \W+ rule and
        become SPACES, splitting one word into two tokens. Copy-pasting an
        Arabic title from a browser routinely carries these.
        (prose.py:63 handles ZWNJ/ZWJ for chapter TEXT only, not for queries.)

    GAP C — MISSING LETTER FORMS AND THE DEFINITE ARTICLE.
        _ARABIC_FOLD omits Persian/Urdu forms that Arabic sites commonly serve:
        keheh U+06A9, farsi yeh U+06CC, heh-with-yeh-above U+06C0. There is
        also no handling of the definite article, which matters for a query
        that is one word of a longer title.
        Note the module deliberately does NOT fold hamza-on-waw or hamza-on-yeh;
        Lucene does not either. Only change that with measured evidence.

    UI GAP — no dir="auto" or lang on #search-input or .hit-title, so Arabic
    renders in an LTR context. EPUB output DOES handle RTL (packager.py).

1.7 ROOT CAUSE — "cannot search again after clicking a result". FOUR CAUSES.

    The UI has NO ROUTER. grep for pushState|popstate|hashchange|location.hash
    in web/app.js returns zero hits. Clicking a hit does not open a detail view;
    it mutates the Add view in place (app.js:704).

    (a) PRIMARY — TWO CONFLICTING '/' SHORTCUT HANDLERS.
        Handler A (app.js:359) focuses #search-input.
        Handler B (app.js:1558) is registered LATER so it runs second and wins;
        when #preview is visible it re-targets #chapter-filter, yanking focus
        straight back out of the box A just focused. The keyboard route to
        search is dead from the first click until a page reload.
        The comment at app.js:1560 ("the search input stays disabled until a
        kind is chosen") is STALE — that behaviour was removed.

    (b) clearResults() (app.js:441) LEAVES input.value INTACT.
        Search fires ONLY on the 'input' event (app.js:332). So:
          - retyping the identical query fires nothing, because the value
            never changes;
          - Enter does nothing: the input is in no <form>, and the Enter branch
            needs cursor >= 0, which clearResults just set to -1;
          - renderRecents() no-ops, because its idle guard needs value < 2 chars.
        The box still reads "berserk", the clear X is still showing, the results
        are gone, and nothing the user types brings them back.

    (c) NO WAY BACK. lastSearch is nulled, there is no Escape handler, no "back
        to results" control, and #preview is a sibling BELOW .finder in the DOM
        — so a 400-chapter list scrolls the search box off screen, while '/',
        the intended remedy, is broken by (a).

    (d) THE CLICK HANDLER SKIPS THE RESET TRIO.
        The kind-chip handler (app.js:315) and the clear button (app.js:351)
        both run: clearTimeout(searchTimer); searchToken++; abandonSearch();
        The result-click handler runs none of them, so a pending debounce or an
        in-flight fetch survives and its late render re-opens #search-results
        on top of the freshly-loaded preview.

    ALREADY RULED OUT — do not spend time here: event listeners are delegated to
    persistent containers so innerHTML='' does not lose them; there is no
    z-index or overlay trap (.toasts is pointer-events:none); #search-input is
    never disabled anywhere.

1.8 THE REQ-8 MECHANISM ALREADY EXISTS — YOU ARE GENERALIZING, NOT INVENTING.

    "Read it on the site but you cannot download it" was already solved once,
    for Noor. Its Download control is account-gated and produced no PDF anchor
    at all; its READER is not gated. The reader serves each page as an SVG
    wrapping a base64 PNG at 2144x3024:

        POST /en/book/read_book?o=<token>                   opens the reader
        GET  /book/read_book_image/0/<book>/<n>/<token>.svg  page n

    curr_reading_pages, book_hash and the token are all in the DOM once the
    reader is open, so pages are minted and handed to the ORDINARY fetcher —
    rate limiting, retries and resume come free. Three hooks carry it:

        Adapter.packaging_for(chapter)   packaging varies per URL, not per class
        Adapter.transform_page(bytes)    unwrap before validate_image()
        packager.write_pdf               a book belongs in a document, not a CBZ

    prose.py + packager.write_epub do the same job for prose novels.
    WP-8 turns this one-off into a documented, reusable recipe.

1.9 THE HIGHEST-LEVERAGE FACT IN THIS ENTIRE PROMPT

R1.  Read HANDOFF.md in full before touching anything. Each line in its

R3.  EVERY new or newly-enabled search source ships a NEGATIVE TEST: a query the

     unanswerable query with something that merely LOOKS like results —
     rizzfables' front-page grid, azoramoon's whole catalogue newest-first,
     arabic-book's latest-posts widget, sunovels' /library, and books.e3raf.
     Nothing structural separates any of them from a real hit. Assume the next
     site does it too. base.query_matches() is the gate.

R4.  Never claim a site works without naming the artifact: absolute path, byte
     size, and page or chapter count. "Search works" is not a claim about
     support. "Preview returned 146 chapters" is not a claim about support.

R5.  NEVER supply site credentials and never solve a login. A site that requires
     an account, subscription, or purchase to reach readable content is
     EXCLUDED — not worked around. The codebase already enforces this well;
     copy those patterns rather than inventing new ones:
        app/adapters/ao3.py         _guard() refuses restricted works outright
        app/adapters/webtoons.py    _LOCK_MARKERS; locked rows dropped from the
                                    listing, not queued to fail
        app/adapters/vcomics.py     lockedChapter island detected and skipped
        app/adapters/royalroad.py   isUnlocked / visible honoured
     Distinguish carefully: anti-bot CLEARANCE (a cf_clearance cookie) is not
     account authentication and is fine. An account is not.

R6.  Normalizing is for matching, NEVER for display. Every caller keeps the
     original string and shows that. Folding is lossy on purpose, and a folded
     match is evidence of relevance, never proof of identity — two genuinely
     different Arabic words can fold together, so nothing in textmatch may be
     used to decide two records are the same work.

R7.  Any relevance change that resurrects catalogue noise is a REGRESSION, even
     if it raises hit counts. The noise tests are the gate, not the enemy.
     Loosening the matcher to "fix Arabic search" is the most likely way to
     break this project. Fix it at the QUERY end (Gap A) first.

R8.  tests/test_search_api.py::test_the_known_adapters_are_filed_correctly is an
     exhaustive id -> content_type dict. Adding an adapter BREAKS it until you
     update the dict. That is the intended tripwire — do not weaken the test.

R9.  Before any completion claim, run and quote:
         python -m pytest -q
         python -m pyflakes app tests
         bash -n startup.sh
     If tests fail, say so with the output. Never report a green run you did not
     see.

R10. Anything that costs you a debugging cycle goes into HANDOFF.md "Findings"
     in the same style as what is already there: what broke, what the evidence
     was, and what the rule is now. That file is why this program is tractable.

R11. Prefer extending an Adapter hook over special-casing a host. If a second
     host needs the same hack, it belongs in base.py. Per-host exceptions are

R12. DISTINGUISH "BROKEN" FROM "BROKEN HERE". This network SNI-filters eight

SECTION 3 — DEFINITION OF DONE: THE SUPPORT LADDER
--------------------------------------------------------------------------------

Maintain SOURCES.md at the repo root. Every site carries EXACTLY ONE tier, with
the evidence that earned it. Only T4 may be advertised in README.md.

  T0  EXCLUDED       Requires an account, subscription, or purchase to reach
                     readable content; or is a shadow library. Record the reason
                     and the date checked. Never added to search_sites.

  T1  REACHABLE      Answers from this network. Use POST /api/connectivity,
                     which already classifies ok / challenge / connection_reset
                     / connect_error / proxy_error.

  T2  SEARCHABLE     Returns real hits for a real query AND returns [] for an
                     unanswerable one. BOTH halves required (see R3).

  T3  READABLE       Content opens anonymously and pages or text are
                     enumerable. No account, no purchase, no unlock.

  T4  VERIFIED       *** THE ONLY TIER THAT COUNTS ***
                     A real artifact is on disk and passes its verifier:
                         verify_cbz / verify_pdf / verify_epub / verify_file
                     (all in app/packager.py). Record: absolute path, byte size,
                     page or chapter count, and the date.
                     For a CBZ, verify_dl.py also decodes every page and flags
                     anything under 600px — a thumbnail rip passes zip integrity
                     and fails a reader.

  TB  BLOCKED HERE   Code believed correct, unverifiable in THIS environment.
                     Only two legitimate reasons, and you must name which:
                       - the host is SNI-filtered from this network
                       - the site needs an interactive Turnstile this container
                         cannot clear
                     Kept in the tree, labelled in SOURCES.md, NOT advertised in
                     README.md, and re-testable on a machine with a real browser.

A site that reaches T2 and stops is a site that LOOKS supported and is not.
That is precisely the failure this program exists to end.

WP-3  ARABIC SEARCH: NORMALIZE AND OPTIMIZE                (requirements 3, 4)
................................................................................
Objective: Arabic spelling variation must stop costing the user results.
Read 1.6 first. textmatch.py is good work — extend it, do not replace it.

WP-8  READER-TO-FILE EXTRACTION      (requirement 8 — SPEND THE MOST TIME HERE)
................................................................................
Objective: the user's most important requirement. If content can be READ in a
browser without an account, our tool must be able to SAVE it — regardless of
whether the site offers a download button, and without ever using one that
requires an account.

Read 1.8. The pattern is proven on Noor. Generalize it into a written recipe in
docs/development.md, then apply it:

  STEP 1  Find where the readable content actually lives. In order of cost:
          server-rendered HTML; a hydration payload (Astro islands, __NEXT_DATA__,
          Nuxt state, inline JSON); an XHR/fetch the reader makes (read it from
          the Network tab or by capturing requests); the rendered DOM last.
          HANDOFF.md records azoramoon server-rendering its ENTIRE 165-chapter
          list into an astro-island props attribute on a page showing 21 anchors.
          Look in the payload before you conclude something is not there.
  STEP 2  Mint stable page/section URLs and hand them to the ordinary fetcher,
          so rate limiting, retries, resume and quality upgrading come free.
          Do not build a private download loop.
  STEP 3  Unwrap in transform_page() if the payload is not a bare image — SVG
          wrappers, base64 data URIs, canvas blobs, XOR/offset-obfuscated bytes.
          Unwrap BEFORE validate_image().
  STEP 4  Choose the container with packaging_for(chapter): cbz for comics,
          pdf for scanned books, epub for prose, file for a real linked document.
  STEP 5  Verify the artifact opens. A CBZ of 1x1 spacers validates perfectly —
          WEBTOON's src is a shared transparent spacer and the real page is in
          data-url. Decode pages and check dimensions.

  Cases already documented that you will meet again:
    - image host 403s without the chapter page as Referer (WEBTOON: 200 with it)
    - a file host answers 200 WITH HTML instead of the file (looks_like_document
      rejects it rather than storing an unreadable "book")
    - 403 over HTTP/2 and 200 over HTTP/1.1, same URL, same headers, same IP
      (downloads.hindawi.org; Fetcher._retry_over_http1 handles it)
    - page URLs that expire and need pages_expire + refresh_pages
    - a base64 file URL hidden in a data- attribute with no anchor anywhere
    - zero-based chapter pagination (sunovels page=1 is the SECOND fifty)
    - css("h2, p") NOT returning document order in selectolax; use traverse()

DONE WHEN: the recipe is in docs/development.md, and at least five sites that
offer NO usable download button have been taken to T4 through their readers.

SECTION 7 — KNOWN TRAPS (EACH ONE ALREADY COST A DEBUGGING CYCLE)
--------------------------------------------------------------------------------

SEARCH AND MATCHING
  - Five sites answer an unanswerable query with something that LOOKS like
    results: a front-page grid, a latest-posts widget, the whole catalogue
    newest-first. Structure cannot tell them apart from real hits. The text can.
  - A 200 from ?s= is not proof a search happened.
  - Relevance must NEVER judge across scripts. These sites index names in
    several writing systems and display one, so an Arabic query legitimately
    lands on a series shown under a romanised name. Such a hit is kept and
    ranked last (SCORE_UNJUDGEABLE), never dropped.
  - Search by author needs an author FIELD, not a cleverer matcher.
  - /api/search?limit= is clamped to MAX_SEARCH_RESULTS for a reason: the number
    goes straight to every adapter, several of which page to reach it.

NETWORK AND BOT CHECKS
  - A 403 or 503 is NOT by itself a bot check. Image CDNs use both routinely.
    Decide on evidence (a Cloudflare marker, or cookies we only hold because the
    host challenged us). Treating status alone as a challenge sent a browser to
    solve Cloudflare against an image node, ten times a chapter.
  - Never solve a challenge just to BUILD a request. Use the passive
    peek_session; get_session solves when nothing is cached.
  - Never synthesise a click for Turnstile when a person could make one.
    Programmatic clicks are marked untrusted and loop that session permanently.
  - patchright's requirement is "Chrome without fingerprint injection". Passing
    viewport, locale, user_agent or ignore_https_errors to
    launch_persistent_context applies detectable CDP overrides. Use
    no_viewport=True and nothing else. Tests assert their absence — do not
    "tidy" them back.
  - cf_clearance is bound to IP AND exact User-Agent. Browser and downloader
    must share an exit path and a UA.
  - An HTTP/2 handshake can be the entire problem: 403 over h2, 200 over h1,
    same URL, same headers, same IP.

CONTENT EXTRACTION
  - A CBZ of 1x1 transparent spacers validates perfectly. Check dimensions.
  - Percent-encoded slugs must be decoded before reading chapter numbers, or
    hex escapes get read as numbers (chapter 372 became chapter 1).
  - urlparse().path truncates a filename at ';' (RFC 2396 params). Use urlsplit.
  - selectolax css("h2, p") groups by selector, NOT document order. Use
    traverse(). Never key a seen-set on id() of a selectolax node.
  - Match a downloadable file on the PATH'S EXTENSION, never on the word
    "download" (which matched a help page in a footer).
  - The file host is often not the site; send the content page as Referer.
  - A hostile file host answers 200 WITH HTML. looks_like_document rejects it.
  - An empty EPUB is what a login wall parses into. write_epub raises instead.

UI
  - [hidden] loses to any author rule that sets display. This UI needs
    [hidden] { display: none !important } — it is already there; do not remove.
  - button:hover:not(:disabled) is (0,2,1) and outscores .tab.is-active (0,2,0),
    and the cursor sits on the control that was just clicked. Repeat the
    background under :hover or the active state appears not to work.
  - Rebuilding a list from innerHTML several times a second destroys scroll
    position. Capture and restore it.

PROCESS
  - grep -c exits 1 on zero matches and will silently truncate an && chain in a
    verification pipeline. It once made a failing test look clean.
  - Fixtures written by hand pass while the adapter is silently wrong. R2.
